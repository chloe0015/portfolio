01 / action editor

More controls, or more focus?

The action editor lets users place animation, sound and logic along a timeline. It lives inside a long-running production ecosystem, so every change has to fit what already exists, while the screens keep getting denser. The question: how much control can one screen carry before it stops being usable?

Below are the three versions, as screenshots from the tool.

~/screens/action-editor-v1.png

Task: make Animation run from frame 3 to 10. actions 0 done

The counter counts clicks and drags in this redrawn demo. It is not a usability measurement.

  1. 01Gave up per-frame precision. Planners said they rarely need that level of control. A coarser model that is faster to use wins.
  2. 02Split the timeline by type. Sound, Animation and Logic each get a labeled, color-coded track, so primary actions can be found at a glance.
  3. 03Simplified what an action looks like. One block per action that you drag and stretch, instead of cells you fill one by one. It is also simpler for engineers to build.

02 / task manager

What state is it in?

Asset production passes through many stages, from request and assignment to submission and review. As requirements kept arriving, with review steps added and rework loops layered on, the interface showed every task with the same weight and an unclear status. I re-mapped the workflow onto three layers of the interface, so each layer answers one question.
